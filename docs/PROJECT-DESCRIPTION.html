1. The problem and the thesis

The problem judges should evaluate

Video makes learning feel easy because recognition replaces recall. A learner can finish a lesson, understand it while watching, and still fail to reproduce the idea tomorrow. The usual fixes add friction: notes split attention, flashcards require authoring, and generic AI quiz tools can ask about a topic rather than the lesson actually watched.

Our thesisThe best next step after a lesson is low-friction retrieval practice: ask the learner to produce an answer, correct the misconception immediately, and schedule a return visit.

What ClipQuest changes

  1. Bring your own lesson. Paste a public YouTube URL and confirm the detected video.
  2. Practice, do not just consume. Choose 5, 10, or 15 questions across multiple choice, true/false, and short answer.
  3. Start immediately. Question 1 is generated and validated first; the rest arrive while the learner answers.
  4. Learn from misses. Every response gets a correction and “Why” explanation. Missed concepts return as adaptive retries.
  5. Keep the progress. Completion shows score, first-try accuracy, missed concepts, mastery, and a one-page cheat sheet. The Library schedules review.

3. The privacy and reliability boundary

The central design choice is where generation runs. ClipQuest Local AI is a Chrome extension: captions are acquired and normalized in the learner’s browser, then sent directly to DeepSeek with the learner’s own key. The Cloudflare Worker never receives the key, captions, prompts, or raw model output.

PUBLIC YOUTUBE LESSON │ ▼ CLIPQUEST WEB ──► LOCAL AI EXTENSION │ captions → clean text │ learner-owned DeepSeek key │ question-by-question JSON ▼ validate ordinal, type, schema, answer, duplicates │ validated questions only ▼ CLOUDFLARE WORKER + D1 auth · ordered storage · deterministic grading mastery · review · Library · profiles

Why the boundary matters

  • Privacy: lesson text and credentials stay outside the server.
  • Economics: inference cost does not scale with learner count.
  • Correctness: the Worker cannot invent a fallback because it has no generation path.

Failure-safe generation

Each question is parsed and validated independently. A malformed question 9 cannot erase accepted questions 1–8. Recovery regenerates only the first missing ordinal with bounded retries. If repair fails, the accepted prefix remains and the learner sees an explicit failure state — never a fake question.

Boundary checkGuarantee
Ordinal and requested typeQuestions arrive in the selected plan and exact order.
Schema and answer mappingMalformed objects are rejected before storage.
Duplicate prompt detectionRepeated questions do not silently enter a bank.
Short-answer rubricServer grading is deterministic and reproducible.
Judge lens: the safety guarantee is structural, not a promise that a model will always behave.

What is verified

  • Ten out of ten tested videos reached question 1 in the current live matrix.
  • Deterministic grading checks passed for the accepted answer set; no invented fallback questions were observed.
  • Questions are stored only after schema, order, type, duplicate, and answer-consistency checks.
  • Production QA artifacts and the current release notes are committed in docs/.
Honest limitationFull-bank completion on the first try reached 5/10 videos in the latest matrix and 8/10 after one retry. The known mismatch failure fails closed, preserving accepted questions instead of substituting content. The in-development Workplace AI chat route is hidden rather than presented as finished.
