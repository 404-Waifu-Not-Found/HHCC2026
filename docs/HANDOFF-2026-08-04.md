## Product behavior implemented

### Complete accepted subtitles

ClipQuest no longer generates from a silent first-caption slice.

- YouTube timed-text and browser text-provider parsers preserve every accepted caption event.
- bilibili subtitle parsing preserves every non-empty subtitle item.
- There is no 12,000-segment `.slice(...)` acquisition path.
- Oversized individual events are losslessly divided into valid segments; malformed or over-budget documents fail instead of being shortened.
- Normalized transcripts are bounded to 60,000 segments and 750,000 canonical characters. These are explicit safety limits, not hidden truncation points.

Every accepted transcript carries a `TranscriptCompleteness` manifest:

- `status: "complete"`
- `truncated: false`
- source and normalized segment counts
- canonical character count
- FNV-1a text fingerprint
- first caption start and last caption end
- expected video duration

The server recomputes the manifest before storing transcript text. Missing, changed, or partial input returns `422 incomplete_transcript`. The manifest is stored with the private transcript and validated again when generation loads it.

### Complete-transcript quiz generation

- Educational classification receives every normalized transcript segment.
- A 5/10/15-question bank is divided into batches of at most five, and all batches run concurrently.
- Every batch receives the complete serialized transcript with line number, segment ID, and timestamps.
- DeepSeek has one 7.5-second attempt per classification/generation request.
- Schema-invalid, unsupported, missing, or timed-out model items are replaced by deterministic evidence-grounded fallback questions.
- Valid questions and fallbacks are committed together in one D1 batch before the job is complete.
- Structured logs record counts, fingerprints, phase latency, validation failures, fallback use, and D1 completion without logging transcript contents, answers, URLs containing tokens, or secrets.

### Learner-selected question types

The learner can select any non-empty combination of:

- multiple choice
- true/false
- short answer

The selection is saved at import, shown again on the create screen, stored on the generation job, honored by DeepSeek and deterministic fallback, and enforced when an attempt selects questions. Ordering questions are neither generated nor served to new attempts. Legacy storage parsing remains defensive so existing rows cannot crash the API.

### Paste-time prework

After a supported link imports successfully, the client immediately starts caption acquisition, completeness verification, transcript upload, and a long-session generation job in the background. The create/generation routes reuse the same idempotency key and completed job when the learner's language and question-type selection still match. Captionless local transcription remains a foreground path because it needs local media processing.

## Source and privacy boundary

- Core inputs are public, playable YouTube and bilibili links.
- Caption text is requested fresh; YouTube caption results are not read from or written to the obsolete source-cache prefix.
- Private transcript text, quizzes, progress, and answers may be persisted for the product flow.
- Raw audio is not written to R2, D1, KV, Cache Storage, IndexedDB, or logs.
- The existing captionless fallback uses a short-lived, authenticated, `no-store` audio response and local Whisper. This is not part of the verified caption-path acceptance below.
- Private, deleted, geo-restricted, active-live, embedding-restricted, age-gated, and upstream-blocked sources are outside the success guarantee. They must fail honestly rather than generate from partial text.
