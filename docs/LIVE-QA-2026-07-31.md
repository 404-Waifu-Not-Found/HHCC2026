## Defects fixed

### Web runtime, routing, and browser hardening

1. The Better Auth Expo bridge called native synchronous SecureStore APIs in browsers. Web now uses same-origin cookie credentials without the native storage getter; a regression test covers it.
2. Dynamic deep links previously returned platform 404s or hydrated home markup as the wrong route. The Worker now serves matching Expo-exported route shells for `/create/:id`, `/generation/:id`, and `/quiz/:id`; unknown routes receive the generated 404.
3. Generated `@expo` asset paths are encoded during finalization, avoiding an unnecessary production redirect.
4. CSP now covers Expo's exact hydration script by build-time SHA-256 hash, uses Zod's supported JITless configuration, retains only the WebAssembly capability needed by local Whisper, and permits only the documented Cloudflare analytics endpoints.
5. Shared web inputs receive stable generated HTML IDs, fixing Chrome form-field diagnostics while retaining accessible labels.
6. Route responses carry hardened CSP, COEP, COOP, CORP, no-sniff/referrer/permissions policies, and an explicit no-transform cache policy.

### Authentication and account safety

1. Verification and recovery email sends are awaited so delivery-provider failures are not falsely reported as success.
2. Verification no longer invokes an unsupported native-cookie auto-sign-in callback.
3. Age-13 confirmation is enforced by a server database hook in addition to the UI.
4. Better Auth rate limiting is backed by D1, with schema alignment supplied by migration `0005`.
5. Account deletion requires password confirmation and removes the user's private transcript/thumbnail objects before relational deletion.
6. Sign-up, sign-in, verification, recovery, reset, and deletion screens guard duplicate submits, disable pending inputs, and show localized recovery errors.
7. Web auth persistence was verified by signing in with a Wrangler-created mobile QA identity and reloading.

### Quiz correctness and mastery

1. Failed initial attempts no longer schedule review.
2. An initial score of at least 80% schedules review; only a later review score of at least 80% reaches Mastered.
3. Old pending reviews are closed before rescheduling to prevent duplicates.
4. Resume responses include mastery and are reconciled with server authority before cached client state is used.
5. Out-of-sequence answers trigger authoritative resume rather than corrupting progress.
6. Ordering prompts start shuffled and require learner interaction.
7. Answer controls are disabled during submission to prevent duplicates.

### Generation correctness and recovery

1. Transcript objects use immutable per-generation keys; grading resolves the transcript associated with that exact generation.
2. Persistent per-user idempotency recovers a lost create response without retranscribing or creating duplicate jobs.
3. D1 is the single job-state authority; the prior racing KV status cache was removed.
4. Retry requeues the stored transcript. Cancellation persists and is checked between AI phases.
5. Queue attempts increment once, ownership is checked before disclosure, and final quiz/job writes are batched with cancellation cleanup.
6. The client persists job identity, resumes polling after restart, aborts stale listeners, exposes retry/cancel, and enforces a 15-minute deadline.
7. Browser transcription explicitly caps input at 20 minutes because compressed and PCM buffers coexist; native retains the 90-minute limit.
8. A valid unseen idempotency key now returns `200 null` instead of an expected 404 that polluted the browser console.
9. Structured API/media errors are parsed for display, including the actionable YouTube-delivery message.
10. Immediate web navigation blurs the active control first to avoid hiding a focused button under an `aria-hidden` route tree.

### YouTube source handling

1. Watch, `youtu.be`, Shorts, Live, and Embed variants are accepted; malformed IDs and lookalike hosts are rejected.
2. The adapter uses an iOS InnerTube client for rich metadata/caption tracks and media because it was the usable client in local source diagnostics.
3. Direct `json3` caption URLs are HTTPS/YouTube-host validated, response-size bounded, parsed into timed segments, and selected with English/Chinese preference.
4. Metadata falls back through a bounded public watch-page parser and then bounded oEmbed, retaining safe reason classifications only.
5. The watch-page balanced-JSON extractor handles braces inside quoted strings and is regression-tested.
6. Reimports during upstream throttling preserve a previously known nonzero duration and source language.
7. Audio-delivery failure now tells the learner that YouTube temporarily blocked delivery and suggests retrying or using another video.

### API, mobile quality, and dependency surface

1. API fixed-window limits use atomic D1 upsert plus expiry cleanup rather than KV read/modify/write races.
2. `/health` reveals only configuration-presence booleans and reports ready only when auth, generation, and email are configured.
3. Auth shells stack below 900 px; 390 px and 320 px layouts no longer clip the left panel.
4. Scroll, keyboard insets, safe-area padding, wrapping footers, responsive cards/thumbnails, and minimum touch targets were corrected.
5. Quiz, completion, generation, settings, and long auth screens remain reachable on short mobile viewports.
6. User-facing recovery/settings fallbacks are localized in English and Simplified Chinese.
7. Removing unused `@cloudflare/vitest-pool-workers` dropped its obsolete Wrangler/Miniflare dependency chain. No forced Expo-breaking audit fix was applied.

## Upstream YouTube limitation

During this run, YouTube challenged Cloudflare's shared Worker egress with its bot/sign-in gate. Local diagnostics established that rich InnerTube metadata and caption-track descriptors are available when the source permits the request, and iOS was the only tested client that could stream an initial audio chunk. From the current live Worker egress, caption content and audio bytes were still blocked for the chosen test video.

The deployed fallback now preserves exact title/duration/language whenever possible and degrades to bounded public metadata rather than a generic title. The UI now provides an actionable retry/alternate-video error. A browser-derived PoToken is not a safe general remedy because tokens are tied to generating client/egress context, and mobile uses DroidGuard. Do not collect user cookies, alter Shadowrocket/system routing, weaken the local-transcription privacy boundary, or send raw audio to an unapproved third party.
