## 2. User requirements and non-negotiable decisions

The product promise is:

> **Paste a video → quiz → build mastery.**

ClipQuest targets learners aged 13 and older, primarily high-school and college students. The intended loop is:

```text
create account
    ↓
paste YouTube or bilibili link
    ↓
use captions, or transcribe locally on the learner's device
    ↓
generate an evidence-backed adaptive quiz
    ↓
answer with immediate explanations and reformulated retries
    ↓
complete a later review to reach Mastered
```

The user explicitly requested all of the following:

- Expo app for web, iPhone, and Android.
- Cloudflare Workers backend at `https://clipquest.ccwu.cc`.
- D1 for durable relational data, KV for ephemeral state/rate limits/tokens, and private R2 for model files, transcript JSON, thumbnails, and other private assets.
- DeepSeek's official API as the primary AI provider, using `deepseek-v4-flash` only.
- DeepSeek's API key entered interactively as a Worker secret, never included in a client bundle.
- Account creation using username, email, password, email verification, recovery, and an age-13 confirmation.
- Optional YouTube history connection with learning-video classification and thumbnail previews.
- English and Simplified Chinese app and quiz languages.
- Local Whisper Tiny transcription on the user's device when useful captions are unavailable.
- No server-side FFmpeg, no Workers AI transcription, no Cloudflare Container, and no raw-audio storage in R2.
- Secrets and external-account setup must be left until the rest of the app is built and verified as far as possible.

Project-specific working rules:

- Address the user as “master” in English or “主人” in Chinese.
- Commit along the way on long tasks.
- Never push unless the user asks.
- Keep final user-facing summaries concise; put deep operational detail in documents like this one.

## 6. On-device transcription and privacy boundary

The architecture intentionally keeps raw media and Whisper inference off the backend.

```text
YouTube/bilibili source
        ↓
Worker validates URL and issues a short-lived, user-bound media token
        ↓
Worker streams source media through /api/media/:token
        ↓
learner device decodes to 16 kHz mono PCM
        ↓
Whisper Tiny runs locally and produces timestamped segments
        ↓
temporary audio is deleted on the device
        ↓
only transcript segment JSON is uploaded
        ↓
Worker stores transcript privately and sends transcript text to DeepSeek
```

### Caption-first behavior

The source adapters prefer existing English or Chinese captions. The speech model is downloaded only if usable captions are unavailable.

### Web path

- Uses quantized `onnx-community/whisper-tiny` through Transformers.js.
- Runs inference inside `public/whisper-worker.js`, not on the React UI thread.
- Prefers WebGPU and falls back to WASM.
- Uses persistent browser caching.
- Works in approximately 30-second overlapping chunks.
- Checkpoints completed chunks locally so a disrupted job can resume.
- Decodes media locally with WebCodecs where supported and an AudioContext fallback.

### iOS/Android path

- Uses `whisper.rn` with `ggml-tiny-q5_1.bin`.
- Downloads the model after installation instead of bundling it into the app.
- Stores the model in the app filesystem and resumes downloads/checkpoints.
- Uses the custom Expo audio-decoder module:
  - AVFoundation on iOS.
  - MediaExtractor/MediaCodec on Android.
- Runs transcription outside the React UI thread.

### Pinned model assets

The repository pins model revisions and creates a SHA-256 manifest:

- Web model revision: `onnx-community/whisper-tiny` at `ff4177021cc41f7db950912b73ea4fdf7d01d8e7`.
- Native model revision: `ggerganov/whisper.cpp` at `98aa99a0a9db05ae2342309f5096248665f7cba3`.
- Native asset: `ggml-tiny-q5_1.bin`, 32,152,673 bytes.
- Browser q8 ONNX assets: approximately 45 MB total.

The pinned files and manifest were prepared and uploaded to the private R2 bucket. The initial app bundle does not contain Whisper weights.

### Guardrails

- Captionless demo videos are limited to 90 minutes.
- Low-memory or low-confidence transcription stops with a clear untrustworthy-quiz error rather than silently generating weak questions.
- R2 remains private.
- Raw audio is streamed, never fully buffered by the Worker, and never stored in R2.
- Only timestamped transcript segments reach the Worker and DeepSeek.

### DeepSeek generation

The Worker is configured for `deepseek-v4-flash` only. The generation pipeline requests:

- Educational-video classification.
- A short video-only primer when the learner has not watched the video.
- Concepts.
- Question variants.
- Evidence segment references.
- Written-answer grading rubrics.

Every question must include transcript segment IDs. The Worker rejects unsupported educational claims/questions, validates DeepSeek JSON with shared Zod schemas, and retries invalid or empty output up to two times.

Generation jobs are sent to `clipquest-generation`. Retry exhaustion or non-retryable validation failure is recorded as a failed job; failed messages can reach `clipquest-generation-dead`.

Official YouTube APIs do not expose watch history. ClipQuest therefore has an experimental, pinned YouTube.js TV device flow behind:

- Import at most 200 history entries.
- Discard timestamps.

- Hide the integration if the private flow stops working.

## 13. Known limitations and risks

These are not secrets, but they require deliberate follow-up:

1. **Fresh Android APK required.** The only verified APK predates Async Storage `2.2.0`.
2. **iOS binary not built.** Full Xcode or EAS authentication/project setup is required.
3. **Secrets absent by design.** Full signup/email/AI end-to-end behavior is not production-complete until the user enters them.
4. **YouTube history is private and fragile.** It must remain feature-flagged off unless explicitly demo-tested with a disposable account.
5. **Source media resolution can drift.** YouTube/bilibili adapters must be smoke-tested against real supported videos before acceptance.
6. **Browser transcription needs real-device testing.** Both WebGPU and WASM paths must be exercised, not just bundled.
7. **Native transcription needs real-device testing.** Expo Go is insufficient; use a development/internal build.
8. **Push delivery needs valid Expo project configuration.** Token registration/UI exists, but production delivery requires the user's Expo setup and device credentials.
9. **Email sender domain must be verified in Resend.** A key alone is not enough if `hello@clipquest.ccwu.cc` is not authorized.
10. **Dependency audit is not clean.** The last npm audit reported 17 issues: 1 low, 11 moderate, and 5 high, largely in transitive Expo/ONNX/build tooling; there were no critical findings. Do not run `npm audit fix --force`, because it may break Expo compatibility.
11. **No complete all-platform acceptance run yet.** Captionless YouTube/bilibili on web/iOS/Android, interruptions, low-memory rejection, notification delivery, and encrypted YouTube unlink still require end-to-end proof.

## 17. Troubleshooting notes

### Android downloads or Gradle fail intermittently

Earlier Gradle/Maven attempts experienced network/TLS flakiness. Prefer a normal Android Studio SDK and a stable connection. Re-run the exact Gradle task after confirming JDK/SDK/NDK versions. Do not replace pinned versions casually and do not reconstruct archives by byte range unless there is no safer option.

### Expo reports an incompatible dependency

The known alignment at handoff is Async Storage `2.2.0` for Expo SDK 57. Run `npx expo install --check` before changing anything. If Expo's expected versions have drifted, verify against the project's installed Expo SDK and official compatibility guidance, then make the smallest explicit update and rerun the full suite/native prebuild.

### iOS pods disagree with JavaScript dependencies

Delete/regenerate the ignored iOS project with `npx expo prebuild --clean --platform ios`, then run `pod install`. Do not treat the previous ignored Podfile.lock as authoritative after the Async Storage change.

### App loads but auth/generation fails

Check whether the four production secrets are still intentionally absent. Do not add fallback hard-coded keys. Confirm D1 migration and Resend domain status only after the user is ready for final integration.

### YouTube history disappears

This is expected if `ENABLE_YOUTUBE_DEMO_HISTORY=false` or the private TV flow fails. Keep it hidden instead of degrading to password/cookie collection. The core paste-link experience must remain independent of this experiment.

### A source video stops resolving

Test whether the failure is source-specific, region-specific, caption-specific, or caused by an upstream YouTube/bilibili change. Preserve the privacy design: do not “fix” it by uploading raw audio to a third-party transcription service.

## 18. Definition of done

ClipQuest is not fully accepted merely because the web shell is live or an APK compiles. Final completion requires evidence that:

1. The full paste → transcript → quiz → later review → Mastered loop works.
2. It works on web, Android, and iOS development/internal builds.
3. English and Chinese caption paths work.
4. Captionless WebGPU, WASM, iOS, and Android local Whisper paths work.
5. Raw audio and Whisper inference stay on the learner's device.
6. Temporary media is deleted locally.
7. Only timestamped transcript text reaches Cloudflare/DeepSeek.
8. Account verification and recovery work with the configured sender.
9. DeepSeek output is evidence-backed and validated.
10. Resume, adaptive retries, and two-stage 80% mastery work.
11. Secrets are present only in Cloudflare's secret store and are absent from every client artifact and repository file.
12. Fresh Android and iOS internal artifacts are delivered and clearly labeled.

Until those checks pass, report ClipQuest as a strong implemented hackathon build with outstanding native/integration acceptance—not as fully production-complete.
